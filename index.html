PRODUCTION LESSONS

실제 실패를 검증 규칙으로 바꾼 두 사례

01 조회 성공과 답변 가능은 달랐습니다.
문제
평가 중 날짜 정보만 조회된 상태에서 모델이 근거 없는 이익 수치를 생성했습니다.
수정
기준일 같은 조회 정보와 실제 집계 행을 구분하고, 필요한 수치가 없으면 답변을 보류하도록 검증했습니다.
확인
집계 행이 없는 경우를 재현해 수치를 만들지 않는지 검사했습니다. 누락값을 0으로 바꾸지 않는 규칙도 유지했습니다.
02 모델이 멈춰도 확인한 근거는 남깁니다.
문제
데이터를 조회한 뒤에도 모델의 빈 응답이나 처리 시간 제한으로 답변이 중단됐습니다.
수정
오류 원인을 구분하고, 제한된 재시도와 최종 응답 시간 확보, 조회 근거를 보존한 대체 답변을 적용했습니다.
확인
조회된 수치는 유지하되 확인하지 못한 원인·순위는 확정하지 않는지 점검했습니다. 복잡한 질문은 완전한 답변 여부를 별도로 평가합니다.

평가는 세 가지를 따로 봅니다.

검색
질문에 맞는 기준과 문서를 찾았는가
숫자
기간·합계·부분합이 조회 결과와 일치하는가
완결성
질문에 모두 답했는가, 미확인 범위를 밝혔는가

92개 기본 질문과 판매 분석 100문항은 별도 평가셋이며 합산하지 않습니다. 평가 문항 수는 테스트 범위이며, 통과율이나 답변 정확도를 뜻하지 않습니다. 제한 답변이 반환된 경우도 질문 전체를 해결한 것으로 보지 않습니다.
